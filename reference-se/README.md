# Chaos Origins Remastered

混沌起源重制版。当前正式基础机制在已通过实机验证的起源、守护者和官方升级流程上，增加以下内容：

- 全简易/军用武器、轻/中/重甲、盾牌和乐器熟练；
- 18 项技能全部获得熟练和精通，不再附加固定数值加成；
- 保留原生种族身份顺序，添加其他官方可选种族的 32 个身份标签与 29 项主动技能/法术；不再额外授予 20 项种族被动，等级技能通过隐藏 `UnlockSpell` 被动保留官方施法属性与长休次数；
- 回响之刃、神导术、法师之手、次级幻影、羽落术、强化跳跃和自我伪装；
- 按存档、按角色保存的能力授予账本。

`1.0.08` 起不再发放变形者面具、数字豪华版服装箱和冒险者包，也不再自动装备面具。已有存档中的物品不会被删除。

官方 SharedDev 数据会按 Progression UUID 覆盖 Shared 旧定义；高等精灵与高等半精灵的种族戏法候选池明确采用“全部授予”规则。重复的舞光术和法师之手按固定种族来源使用魅力，其余高精灵候选戏法使用智力。龙裔吐息、龙族血统抗性、重复黑暗视觉、`HumanVersatility` 与影心畏狼效果明确排除。

七项起源身份在新角色上默认全部开启，可由 MCM 总开关或七项独立开关控制；战斗中禁止切换。身份只直接提供对应的官方标签与即时能力：阿斯代伦吸血、威尔边境之刃、卡菈克汗液免疫与狂怒烈焰；盖尔、莱埃泽尔、影心和邪念只有标签。项目不修改职业 Progressions、专长成长、角色模板或视觉资源。

## 混沌机制与 MCM

MCM 只允许主机修改当前主控混沌角色，所有角色开关随存档保存并在战斗中锁定。起源身份只直接提供官方标签与即时能力；阿斯代伦飞升、盖尔的耐色瑞尔魔球/幽影能力/成神、威尔的两项契约奖励、卡菈克的两阶段引擎升级，以及邪念的杀戮者形态/律令：死亡，均由对应官方剧情结果触发，绝不按等级发放。真实起源队友完成相应结果，也可让混沌角色认领奖励；已认领的永久奖励不会因关闭身份而被收回。

本 MOD 不复制炼狱长袍、炼狱刺剑、幽影提灯等剧情装备，只同步明确列出的能力和状态。盖尔成神会保留混沌角色当前等级，不会将其设为 20 级。上述新剧情奖励行为尚未完成游戏内验收。

- 十八项技能：全部获得熟练与精通，按官方熟练加值成长，不附加固定 `+5`；
- 混沌受创：从角色一个回合开始到下个回合开始之间，首次受到攻击或法术伤害时抽取一次正面、负面或潮湿结果；15 项负面结果可分别关闭；
- 混沌迷失与混沌之力：敌方造成的受创负面结果会累积迷失并按递增概率转化；击杀也可独立积累并判定混沌之力；
- 混沌开天辟地：每消耗 3 点混沌之力，恢复生命与本回合资源、清除有害状态，并获得一回合强化与一次混沌必杀；
- 混沌两仪：直接伤害的一半照常结算，另一半按目标独立进入混沌轮盘；
- 混沌孤注：用命中惩罚换取命中后的最终伤害翻倍，等级提高后惩罚降低且次数增加；
- 混沌回响：直接伤害按等级概率追加力场伤害或治疗仍存活的受击目标；
- 混沌强袭：12 级解锁，每次短休一次，将一次攻势推向必成并使最终伤害翻倍；
- 调试日志：默认关闭，仅在排查机制时从 MCM 开启。

关闭任一机制会立即移除本 MOD 为该机制授予的能力或激活状态；关闭混沌两仪会同时清除该角色尚未结算的轮盘伤害。

## 当前测试辅助功能

“12级测试经验”保留在 MCM 中但默认关闭。开启后只把当前混沌角色的累计经验补足至 `100000`，不直接执行升级，仍由玩家逐级确认升级界面；关闭不会扣除已经获得的经验。

进入存档后可在 BG3SE 服务端控制台使用以下测试命令：

- `!cor_power <正整数>`：给当前主控混沌角色增加指定数量的混沌之力，并立即同步可见 BUFF 层数；
- `!cor_allin`：把当前主控混沌角色的混沌孤注使用次数恢复至当前等级上限。

命令要求当前主控角色为混沌起源且对应机制已开启；参数错误或状态不符合时会直接显示错误。

## 构建

首次构建或游戏更新后，先从本机游戏 PAK 准备最小验证数据：

```powershell
& .\prepare-official-data.ps1 -GameDataPath '<BG3 Data目录>' -LslibPath '<LSLib.dll路径>'
```

然后验证并构建：

```powershell
& .\verify.ps1
& .\build.ps1 -LslibPath '<LSLib.dll路径>'
```

`package-files.json` 是受版本控制的 PAK 文件清单。构建会先做机制与官方标识检查，再核对 staging 清单，最后反向解包并逐文件比较 SHA-256。首个成功构建为 `1.0.01`，以后每次成功构建递增末位版本。
