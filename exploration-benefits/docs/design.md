# 战斗外探索增益：独立 MOD 设计

## 已确认要求

- 新建独立 MOD，不向混沌起源添加功能，不修改或替换混沌起源安装包。
- 对全队正式队员生效，包括主控和已入队同伴；不包含普通友善 NPC 或召唤物。
- 每个角色独立判断战斗状态，不采用“任一队员参战就全队停用”。
- 战斗外提供大跳、羽落、动物交谈、黑暗视觉、防滑倒、忽略恶劣地形六类效果。
- 角色进入战斗时移除本 MOD 的上述增益，脱战后自动恢复。

## 拟采用实现

独立模块名 ExplorationBenefitsStory，显示名称“战斗外探索增益”，初版 1.0.0.1。使用独立模块 UUID、状态标识和 Story 数据库；不依赖混沌起源、NMCM 或 Script Extender。

每名正式队员获得默认开启的“探索便利”被动开关。开关独立并随存档保存；关闭立即清理本 MOD 增益，脱战不自动重新开启。开启时仍以该角色未参战为获得增益的前提。战斗只暂停增益，不改变玩家开关选择。不接入混沌起源菜单。

使用 MOD 专属状态实现六类效果。核对本机原版定义后复用相应机制，不能直接删除原版同名状态。原版法术、药剂、装备提供的同类增益不由此 MOD 清理，也不承诺不同来源叠加后的数值。

“防滑倒”限制为地表滑倒，不扩展为所有倒地免疫；“忽略恶劣地形”不等于免疫火焰、酸液等地表伤害。若原版定义不能独立实现这一范围，必须明确报告限制，不能悄悄扩大免疫范围。

通过加载完成、入队、进入战斗、离开战斗等原生事件同步。同步时查询角色当下是否参战，不仅依赖事件名称。已在战斗中的角色读档后不能获得探索增益。离队时清除本 MOD 增益。不引入持续高频全队轮询。

## 验证与交付

1. 先建立缺少状态、缺少战斗判断、误删原版状态时会失败的检查，再编写实现。
2. 编译 Story，检查独立身份、引用、最终包文件清单及编译结果。
3. 输出“战斗外探索增益-1.0.0.1.pak”至桌面的“博德之门3mod”目录，附使用和测试说明。未经安装请求，不自动结束游戏或修改加载顺序。
4. 游戏验收：两名分离队员只有其中一人参战时，仅该角色失去增益；脱战恢复；战斗中读档不误发；离队清理；玩家自己施放的同类原版法术不被移除；六类效果逐项实测。

静态检查、编译成功与包哈希只能证明构建产物，不能代替上述游戏内验收。
