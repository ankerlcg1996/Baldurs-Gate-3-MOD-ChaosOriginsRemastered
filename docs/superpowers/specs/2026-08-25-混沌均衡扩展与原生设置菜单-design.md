# 混沌均衡扩展与原生设置菜单设计

## 目标

为 `ChaosOriginsStory` 增加不依赖 NMCM、MCM、ImprovedUI 或 Script Extender 的原生设置页，并以现有两仪、受击轮盘、混沌之力、命运改签、孤注、开天辟地和掌控混沌为基础，加入少量可控的新机制。

最终设置页参考 `前置-NMCM-原生菜单显示.pak` 的原生 XAML 状态机结构，但使用独立模块路径、状态名、事件 UUID 和本地化。`AbsoluteWrath.pak` 只用于核对原生资源与 Story/Stats 组织方式，不复制其 SE 代码。

## 约束

- 保持纯 Story 实现。
- 不重新加入种族主动技能或额外官方种族被动。
- 不恢复已经删除的“混沌回响”。
- 不增加随机死亡、永久失控或敌我不分效果。
- 不修改官方对话文件。
- 不隐藏错误，也不在读取失败时伪造默认值。
- 每次成功构建都将最后一段版本号加一。
- 静态验证、PAK 构建、安装和游戏内验收分别报告。

## 实现路线

### 方案选择

采用“独立设置后端 + NMCM 式暂停菜单 + 原生设置手册”的组合。

- Story 数据库保存每名混沌角色的设置。
- 暂停菜单提供真正的原生图形界面。
- 设置手册使用原生链接技能容器，作为暂停菜单发生 UI 冲突时的备用入口。
- 两个入口调用同一组固定 Story 请求，不维护两份配置。

纯 Story 技能无法直接打开任意自定义 XAML 状态，因此设置技能不会冒充图形界面入口。图形界面必须通过暂停菜单状态机打开。

## 原生设置界面

### 入口

键盘暂停菜单和手柄暂停菜单各增加一个“混沌起源设置”按钮。按钮只在进入游戏后的暂停状态出现，不进入主菜单、角色创建或加载界面。

按钮打开独立模态状态 `COS_CFG_MENU`。页面使用 BG3 原生背景、标题、按钮、滚动区域和声音资源。关闭方式包括右上角关闭、ESC 和手柄 B。

### 页面结构

设置页分为三个标签。

#### 核心机制

| 设置 | 默认值 | 控制内容 |
| --- | --- | --- |
| 混沌两仪 | 开启 | 攻击伤害轮盘及迟发裁定 |
| 受击轮盘 | 开启 | 每回合首次有效受击结算 |
| 混沌之力 | 开启 | 获取、迷失积累与资源转化 |
| 击杀之力 | 开启 | 击杀带来的混沌之力 |
| 混沌孤注 | 开启 | 孤注技能、充能和倍率 |
| 命运改签 | 开启 | 攻击时多次判定并选择最优结果 |
| 混沌开天辟地 | 开启 | 开天辟地技能及资源消费 |
| 混沌强袭 | 开启 | 强袭反应及等待结算状态 |
| 掌控混沌 | 开启 | 1–12级点数、调律和厄兆纠偏 |

关闭核心机制时停止新的触发。已有永久成长、当前混沌之力、迷失层数和已经消费的掌控点不删除。关闭孤注、命运改签、强袭或两仪时，清理尚未结算的临时等待状态。

关闭混沌之力后，开天辟地和命运改签因缺少启用中的资源系统而暂停，但各自的开关值保持不变。关闭掌控混沌后，系统隐藏选择技能并暂停路线对轮盘的修正；升级仍记录应得点数，重新开启后恢复未消费点数、路线层数和选择技能。

#### 身份能力

分别控制阿斯代伦、盖尔、莱埃泽尔、影心、威尔、卡菈克和邪念七种起源身份。

- 默认全部开启。
- 提供“全部开启”和“全部关闭”。
- 关闭时移除对应官方标签与即时身份能力。
- 已经通过剧情取得的永久奖励和一次性领取记录保持不变。
- 不在此页显示种族主动技能或额外种族被动。

#### 随机结果

分组显示受击轮盘中的正面、负面和平息结果。每个具体状态可以单独开启或关闭，并提供组内全选和取消。

- 关闭结果后，它不进入对应类别的权重池。
- 正负类别的总概率仍由掌控混沌计算。
- 具体结果关闭不会把负面概率转成正面概率，也不会产生空结果。
- 某类别没有任何可用结果时，界面拒绝关闭最后一项并显示原因。
- 强效状态保持低权重，不因关闭其他状态自动变成等概率。

### 当前角色与权限

设置对象为主机当前控制的混沌角色。

- 非混沌角色打开页面时只显示说明，不发送修改请求。
- 战斗中可以查看，不能修改。
- 多人游戏第一版只允许主机修改其当前控制角色。
- 切换控制角色后，重新打开页面读取新角色的配置。

### 交互规则

- 修改立即生效，不设置额外“应用”按钮。
- 每行显示明确的“开启”或“关闭”，不只依赖颜色。
- 页面底部提供“恢复默认”。
- 恢复默认只恢复开关，不清空资源、成长点、剧情奖励或计数账本。

## 设置手册

每名混沌角色获得一个“混沌设置”技能。技能打开原生链接技能容器，包含：

- 核心机制设置；
- 身份能力设置；
- 随机结果设置；
- 恢复默认；
- 混沌机制说明。

每个子项只执行固定开关操作。当前已经开启的项目只显示“关闭”，当前已经关闭的项目只显示“开启”。手册与图形界面共用权限和战斗锁。

## 持久化与数据流

Story 数据库是唯一真实来源：

- `DB_COS_ConfigMechanic(Character, Key, Enabled)`；
- `DB_COS_ConfigOrigin(Character, Key, Enabled)`；
- `DB_COS_ConfigWound(Character, Key, Enabled)`。

初始化只补充缺少的键，不覆盖已有值。旧存档首次载入时，正式功能默认开启；已经明确废弃或尚未解锁的功能不建立伪造记录。

配置随当前游戏存档保存，不跨存档共享。纯 Story 版本不承诺像外部 MCM 一样保存全局客户端配置。

每项配置对应一个 `COS_CFG_*` 隐藏被动。隐藏被动只向 XAML 和设置手册回显当前状态，不承担持久化。数据流为：

1. XAML 或手册发送固定操作。
2. Story 校验角色、控制权、战斗状态和键。
3. Story 更新数据库。
4. Story 应用或清理对应能力。
5. Story 同步隐藏回显被动。

系统不接受由界面传入的任意字符串键。每个操作使用独立的 TutorialEvent UUID 或固定子技能。

## 均衡扩展

### 混沌记忆

某个具体轮盘状态仍在生效时，同一类别再次抽取会暂时排除该状态，并从该类别的剩余权重池抽取。该规则不重新判定正负类别，因此不改变掌控混沌的正负数学期望。

若该类别只剩一个有效结果，允许它重复，避免递归重投或空结算。

### 轮盘蓄能

以下两个事件共享“每回合最多一次”的资源锁：

- 两仪得到“技能原样不变”；
- 受击轮盘得到“平息”。

首次满足条件时获得1点混沌之力。该规则降低资源获取难度，但不能通过多段攻击或多次受击在一回合内反复获取。

### 强效结果余波

只为加速、眩晕、沉默、倒伏、隐形等高影响状态配置轻微反向余波。

- 强正面效果结束后附带轻微短期代价。
- 强负面效果结束后附带轻微短期补偿。
- 余波不抵消原状态，不叠加，不造成失控或直接死亡。

每种余波使用独立状态和明确说明，不使用一个隐藏随机池代替说明。

### 两仪·迟发裁定

迟发裁定是低权重正面结果。它先计算目标总伤害，再拆分当下伤害和下一回合的力场结算，避免低数值百分比被取整为零。

| 等级 | 当下伤害 | 目标总伤害 |
| --- | ---: | ---: |
| 5–8 | 原伤害的80% | 原伤害的110%，向上取整 |
| 9–12 | 原伤害的75% | 原伤害的115%，向上取整 |
| 13–19 | 原伤害的70% | 原伤害的120%，向上取整 |
| 20–29 | 原伤害的70% | 原伤害的125%，向上取整 |
| 30以上 | 原伤害的70% | 原伤害的130%，向上取整 |

下一回合伤害等于目标总伤害减去当下实际结算值。系统必须记录攻击者、目标、待结算整数和触发回合，并阻止该伤害再次触发两仪或受击轮盘。

力场伤害、抗性绕过、击杀归属、多目标和多段攻击属于游戏内验收项。静态编译不能证明这些行为正确。

### 失败取样

每次短休后，第一次非战斗能力检定失败使角色获得1点混沌之力。攻击、豁免、死亡豁免和被动环境检定不计入。若 Story 无法可靠区分这些事件，该功能保持关闭并报告明确失败，不扩大为所有失败事件。

### 13–30级里程碑

13级后不再增加掌控混沌选择点，改为解锁机制：

- 13级：解锁迟发裁定120%；
- 16级：解锁原样结果的轮盘蓄能；
- 20级：迟发裁定提高至125%；
- 24级：强负面余波补偿延长1回合；
- 27级：每场战斗第一次平息额外获得1点混沌之力；
- 30级：迟发裁定最高提高至130%。

## 文件边界

### GUI

- `Mods/ChaosOriginsStory/GUI/Pages/COS_ConfigEscButton.xaml`；
- `Mods/ChaosOriginsStory/GUI/Pages/COS_ConfigEscButton_c.xaml`；
- `Mods/ChaosOriginsStory/GUI/Pages/COS_ConfigMenu.xaml`；
- `Mods/ChaosOriginsStory/GUI/Pages/COS_ConfigMenu_c.xaml`；
- `Mods/ChaosOriginsStory/GUI/StateMachines/Keyboard.xaml`；
- `Mods/ChaosOriginsStory/GUI/StateMachines/Controller.xaml`；
- `Mods/ChaosOriginsStory/GUI/metadata.lsf`。

状态机以 NMCM 当前参考文件为结构基线，逐节点替换名称和资源路径。不得从旧提交直接恢复整套已导致崩溃的 XAML。

### Story 与 Stats

- 新建 `COS_Config.txt` 处理配置生命周期和固定请求。
- 现有机制 Goal 只读取配置数据库或调用单一配置查询过程。
- `ChaosConfig.txt` 保存回显被动、设置技能和子技能。
- 新玩法继续放入各自机制文件，不把伤害结算塞入配置 Goal。

### 构建

精确清单加入 GUI、TutorialEvents、Stats 和四语本地化。构建验证拒绝 SE、MCM、NMCM 模块路径或依赖，并对最终 PAK 反向解包逐文件校验。

## 分阶段门禁

原生菜单曾导致无法进入新游戏，因此不得一次性恢复全部旧文件。

### 第一阶段：菜单空壳

- 只加入暂停菜单按钮、空白设置页和关闭操作。
- 页面不发送 Story 请求，也不读取角色 Passives。
- 构建并安装后，必须实测主菜单、新游戏、读档、暂停、关闭页面和手柄。

### 第二阶段：设置后端

- 加入每角色数据库、固定事件、回显被动和核心机制开关。
- 实测保存、读档、换地图、升级、洗点与多人主机控制。

### 第三阶段：完整菜单

- 加入身份、随机结果、全选、取消和恢复默认。
- 加入设置手册并验证两个入口读取同一数据。

### 第四阶段：均衡扩展

- 先加入混沌记忆与轮盘蓄能。
- 再加入强效余波和13–30级里程碑。
- 迟发裁定与失败取样单独构建、单独实机验收。

每个阶段只在上一阶段完成游戏内验收后进入下一阶段。每次构建按项目规则增加最后一段版本号。

## 验证标准

### 静态和编译

- XAML 状态、页面名、资源路径和 TutorialEvent 一一对应。
- 每个配置键只有一个 Story 写入入口。
- 配置初始化只补缺失键。
- 关闭最后一个类别结果的请求被明确拒绝。
- StoryCompiler、资源编译、本地化编译和反向解包通过。
- PAK 不包含 SE、MCM 或 NMCM 依赖。

### 游戏内菜单

- 安装菜单空壳后可以创建新游戏和载入存档。
- 键盘、鼠标和手柄均可打开、操作、关闭页面。
- 战斗中只读，非混沌角色不发送修改请求。
- 保存、读档和换地图后保留每名角色的设置。
- 恢复默认不清空资源、成长和剧情奖励。

### 游戏内玩法

- 逐项关闭核心机制后没有新触发或残留等待状态。
- 关闭具体结果后，同类别权重按剩余权重重新抽取。
- 混沌记忆不改变正负类别概率。
- 轮盘蓄能每回合最多触发一次。
- 迟发裁定的当下值、延迟值和总值符合表格，并且不递归触发。
- 13、16、20、24、27和30级里程碑分别生效。

只有相应阶段通过游戏内验收，才能声明该阶段完成。
