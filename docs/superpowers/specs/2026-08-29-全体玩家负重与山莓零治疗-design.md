# 全体玩家负重与山莓零治疗设计

## 目标

本次发布包含两项独立改动：

1. 所有玩家角色获得原负重上限的 50 倍。
2. 原版山莓保持无限使用，并尝试通过 `RegainHitPoints(0)` 进入治疗结算。

发布版本为 `1.0.1.59`。本次不自动改用恢复 1 点；若游戏仍将 0 点恢复判定为无效果，下一版 `1.0.1.60` 再改为 `RegainHitPoints(1)`。

## 作用范围

负重增益作用于官方 `DB_Players` 中的角色，包括主角、已加入的同伴和雇佣兵。普通 NPC、敌人和召唤物不获得该增益。功能不要求角色选择混沌起源。

山莓继续覆盖官方物品：

- Object Stat：`CONS_Berry`
- RootTemplate MapKey：`b0943b65-5766-414a-903d-28de8790370a`
- RootTemplate Name：`GEN_CONS_Berry`

神莓术生成物及官方状态 `FOOD_FRUIT_GOODBERRY` 保持不变。

## 负重实现

新增隐藏被动 `COS_GlobalCarryCapacity50x`：

```text
new entry "COS_GlobalCarryCapacity50x"
type "PassiveData"
data "Properties" "IsHidden"
data "Boosts" "CarryCapacityMultiplier(50)"
```

新增原生 Story 目标 `COS_GlobalPlayerBenefits.txt`。目标只负责同步全体玩家增益，不接入混沌起源标签或设置开关。

同步过程检查 `HasPassive`，仅在缺少被动时调用 `AddPassive`。以下入口触发同步：

- `LevelGameplayStarted`：遍历 `DB_Players`，覆盖新档和旧存档。
- `GainedControl`：覆盖新取得控制权的角色。
- `CharacterJoinedParty`：覆盖后来加入的同伴和雇佣兵。
- `RespecCompleted`：洗点完成后恢复被动。

重复触发不会叠加被动。角色离队时不删除被动；重新入队仍只保留一份。

## 山莓实现

根因是 `COS_RASPBERRY_ZERO_HEAL` 只继承官方 `FOOD` 的表现，没有 `OnApplyFunctors`。物品会施加状态，但不会进入治疗结算。

本次在该状态中加入：

```text
data "OnApplyFunctors" "RegainHitPoints(0)"
```

RootTemplate 继续使用：

```xml
<attribute id="Consume" type="bool" value="False" />
<attribute id="StatsId" type="FixedString" value="COS_RASPBERRY_ZERO_HEAL" />
```

官方数据没有在运行 Functor 中使用 `RegainHitPoints(0)` 的先例。因此，静态校验只能证明语法、资源和引用正确，不能证明游戏会显示治疗结算。若游戏内仍无治疗表现，下一版将唯一地把数值改为 1。

## 验证

自动验证必须覆盖：

- 隐藏被动唯一存在，类型为 `PassiveData`，Boost 精确为 `CarryCapacityMultiplier(50)`。
- 四个 Story 入口只对 `DB_Players` 调用同一同步过程。
- 同步过程检查被动缺失后再授予，避免重复叠加。
- 山莓状态唯一包含 `OnApplyFunctors "RegainHitPoints(0)"`。
- 山莓模板继续设置 `Consume=False`。
- 代码和状态均未覆盖 `FOOD_FRUIT_GOODBERRY`。
- Story 编译、IR 证明、Stats 解析、资源编译、38 文件打包和反向哈希验证通过。
- 版本从 `1.0.1.58` 递增到 `1.0.1.59`；安装包和构建包 SHA-256 相同。

游戏内验收必须单独确认：

1. 主角、同伴和雇佣兵的负重上限均变为原来的 50 倍。
2. 普通 NPC 和召唤物不获得增益。
3. 旧存档当前队伍和后来加入的角色都获得增益。
4. 洗点后增益仍存在或立即恢复。
5. 山莓使用后数量不变，生命值不变，并出现治疗表现或治疗日志。
6. 神莓术生成物仍按官方规则消耗和治疗。

静态验证、构建和安装不能替代这些游戏内验收。

## 发布流程

实现通过测试和复核后，只运行一次 `build.ps1`。构建成功后关闭仍在运行的 BG3，备份已安装 PAK，安装 `1.0.1.59`，比较 SHA-256，并将功能分支和 GitHub `main` 快进到发布提交。
