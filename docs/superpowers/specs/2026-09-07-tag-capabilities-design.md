# 标签能力与分组批量控制：已确认需求

基线 1.0.1.83。用户已验证起源身份开关与快捷栏同步、标签出现在属性中。

- 超过五项的分组提供全选和反选；原生标签及熟练不得删除。
- 瓦罗魔法眼上方增加两个默认关闭的总开关。
- 标签种族能力：按原生等级获得对应法术/能力；关闭只撤销本功能授予。
- 标签种族装备效果：开启后允许选择的种族标签满足装备条件；关闭保留真实种族资格。
- 不改变现有混沌概率，不使用 Script Extender，不改用户存档结构之外的游戏文件。
- 菜单标题与镜像被动比较键分离，沿用 .83 修复后的规则。

## 已核查的实现边界

当前分组 Origin=7、Tag=32、Weapon=31，另有核心机制9项、官方种族被动20项。
Armor=4、Instrument=1不添加批量按钮。

本机 Gustav.pak 的 MAG_Githborn_Mindcrusher_Greatsword_Passive 等装备被动
直接使用 Tagged('GITHYANKI', context.Source)。因此单纯给角色增设一个总开关
不足以实现关闭后的隔离，必须审计并改写对应装备判定，保留原生资格路径。
不得通过清除身份标签来假装关闭装备效果。

本机种族 Progressions 的 AddSpells 同时携带施法属性、AlwaysPrepared 和
UntilRest 等授予参数；不得用裸 AddSpell 代替，避免丢失原生冷却/来源。
SelectSpells/SelectSkills 属于角色创建选择，不等同于全部自动发放。
用户已明确选择仅自动发放原版固定能力；不增加自选戏法或龙裔血统选择入口。

## 安全边界

不得对官方法术或被动直接 RemoveSpell/RemovePassive 来实现撤回；采用独立
来源承载，并验证本来具有同一能力、之后从职业再次学到该能力两种情形。
装备覆盖需枚举精确条件，其他模组的未知装备不宣称全覆盖。

## 用户后续调整（1.0.1.85 之后）

- 批量按钮统一居中，改为“全部开启 / 全部取消”；后者关闭本组已开项，不再反选。
- 官方种族被动沿用原有两个批量按钮，不重复添加。
- 内部 VO_POSTPROCESS 已从菜单移除，身份标签为31项。
- 下一阶段仅交付标签种族固定法术与主动能力，总开关默认关闭，位于瓦罗之眼上方。
- 已有种族被动菜单继续独立管理被动；不额外叠加种族属性、移动力或自选能力。
- 种族装备资格总开关仍留待后续，不宣称已完成。

授予数据来自本机原版 Shared 与 SharedDev 按 Progression UUID 覆盖合并后的22条 AddSpells 记录。
通过18个独立隐藏被动承载 UnlockSpell，保持原版法术ID、施法属性和休息限制。
地狱叱喝的反应资源独立承载；首次同步时已有该原版种族法术的角色不增加第二份资源。
新来源只撤销自身被动，不调用 RemoveSpell 清除原生或职业法术。
