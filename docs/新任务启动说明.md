# 新 Codex 任务启动说明

## 使用方式

新开一个 Codex 任务，将工作目录设为：

```text
C:\Users\ankerlcg\Desktop\chaos-BG3-mod-story
```

然后发送以下提示词：

---

我要从零开始编写《博德之门 3》混沌起源 Story Lite 版。

请先完整阅读：

1. `README.md`
2. `docs/项目构造与迁移说明.md`
3. `docs/功能迁移矩阵.md`
4. `story-src/README.md`

`reference-se/` 是当前 SE 正式版 `1.0.25`、提交 `3a9834f4d078fab3488846b80579a6e6776d641c` 的只读源码快照，只能用于理解功能、资源和规则，禁止在里面继续开发。所有 Story 源码必须写入 `story-src/`。

本项目必须使用原生 Story 实现，不使用 Script Extender，不使用 MCM。保留混沌起源、全部角色与种族身份、种族主动技能、剧情结果奖励和简化随机机制；不恢复额外种族被动。混沌两仪、混沌回响和伤害翻倍必须按 Story 能力重新设计，不能假装复刻 Lua 的伤害 Hook。

请先检查仓库状态和本机可用的 BG3/LSLib/Story 编译工具，再向我确认 Story Lite 是与 SE 版共存还是互斥。未经确认不要生成最终模块 UUID。之后先给出最小起源阶段的实现设计，获得批准后再编码。

开发规则：

- 每个阶段单独 Git 提交；
- 修改前确保已有阶段已提交，便于逐步回退；
- 不增加猜测性 fallback；真实错误应明确暴露；
- 先验证角色创建、默认男性半精灵、骗子背景、守护者和 1–12 级升级；
- 最小起源通过前不加入身份、剧情奖励或随机机制；
- 构建时验证精确文件清单，并反向解包逐文件比较 SHA-256；
- 编译成功、安装成功和游戏内通过必须分别报告；
- 安装 PAK 前先确认游戏已关闭。

请从“检查现有工具链和确认共存策略”开始，不要直接复制 Lua。

## 新任务第一批需要回答的问题

1. Story Lite 与 SE 版是否需要同时安装、同时出现在角色创建界面？
2. Story 模块是否采用全新名称、UUID 和 Stats 前缀？
3. 七个初始法术与混沌强袭是否继续保留？
4. 开发期是否需要原生 Story 测试技能来增加混沌之力、孤注次数或经验？
5. 重新设计后的两仪、回响和强化伤害，期望偏强、均衡还是高风险高回报？

这些问题会改变模块身份、存档兼容和机制定义，应逐项确认，不应由开发者猜测。
