# 混沌起源 Story Lite：项目构造与迁移说明

## 1. 文档目的

本文件让一个没有旧对话上下文的新任务能够继续开发原生 Story Lite 版，同时保证现有 SE 正式工程不被修改。

当前仓库只是“独立工程骨架 + SE 参考快照”。Story 版尚未开始编码、编译或实机验证。

## 2. 已确认的产品方向

Story Lite 版是独立实现，不是把扩展名从 Lua 改成 Story：

- 保留可创建的混沌起源角色；
- 保留“本起源代表所有角色和所有种族”的身份设计；
- 保留全部种族身份标签和额外种族主动技能/法术；
- 不额外发放全部种族被动；
- 保留基础技能体系和已经确定的剧情结果奖励；
- 保留简化后的随机玩法；
- 移除 Script Extender 与 MCM 依赖；
- 重新设计混沌两仪、混沌回响和伤害翻倍，不要求复刻 SE 的逐次伤害 Hook；
- 混沌受创与混沌两仪仍是角色主要被动，不作为可关闭的 MCM 项目。

原 SE 项目的 `100000` 经验测试开关依赖 MCM。Story Lite 版是否保留测试入口，应在新任务中单独决定，不能默认做成正式常驻能力。

### `reference-se/`

来源为 SE 仓库提交 `3a9834f4d078fab3488846b80579a6e6776d641c`，版本 `1.0.25`。只复制该提交受 Git 管理的 54 个文件，所以不会携带原仓库远程地址、分支、工作树、PAK、备份或临时文件。

参考快照的主要区域：

- `source/Public/ChaosOriginsRemastered/Origins/Origins.lsx`：起源注册；
- `source/Public/.../Stats/Generated/Data/`：被动、状态、法术、资源和中断定义；
- `resource-src/`：起源标签和图标 TextureBank 的可编译资源；
- `localization-src/`：中、英、日、韩文本源；
- `official-data/`：经审核的官方种族目录数据；
- `source/Mods/.../ScriptExtender/Lua/`：SE 运行时行为参考；
- `build.ps1`、`verify.ps1`、`package-files.json`：SE 构建和反向校验参考。

### `story-src/`

所有 Story 新代码、Goals、数据库声明、Stats 和资源均放在这里。不得让 Story 构建脚本从 `reference-se/` 直接打包文件，否则参考快照会失去“已知旧行为”的边界。

## 4. 当前 SE 架构

### 4.1 静态数据层

- `Origins.lsx` 注册一个自由种族、自由职业、自由体型的混沌起源，默认男性半精灵外观模板，背景为骗子。
- `Passive.txt` 包含起源标记、武器护甲熟练、18 项技能熟练与精通、七个初始法术容器、三个种族主动能力解锁容器，以及七项起源身份开关被动。
- `Status_BOOST.txt` 保存七项起源身份的隐藏标记状态。
- `ChaosCore.txt` 定义混沌之力、混沌孤注、开天辟地、回响、两仪、强袭等核心 Stats。
- `ChaosRuntime.txt` 定义受创结果、计数显示、日志状态和两仪结果状态。
- `Interrupt.txt` 定义混沌强袭的中断能力。
- `ActionResourceDefinitions.lsx` 定义自有资源；自定义图标由 DDS、图标 LSX 和 TextureBank 共同提供。

### 4.2 SE 运行时层

| 模块 | 当前职责 | Story 迁移结论 |
|---|---|---|
| `BootstrapServer.lua` | 生命周期、Osiris 监听、同步调度、MCM 服务端、测试控制台 | 不能复制；拆成 Story Goals 和事件数据库 |
| `BootstrapClient.lua` | 自定义 MCM 页面 | 删除 |
| `McmProtocol.lua` | MCM 白名单和通信协议 | 删除 |
| `ChaosState.lua` | 按存档、按角色持久化状态与严格迁移 | 改为 Story DB、角色状态或可持久化 Flag |
| `GrantLedger.lua` | 幂等授予/移除标签、被动、法术和状态 | 用 Story DB 记录已授予项目，规则必须幂等 |
| `ChaosCharacter.lua` | 混沌角色识别和玩家枚举 | 用起源标签/被动与 Story 查询替代 |
| `BaseFeatures.lua` | 基础被动与初始法术同步 | 尽量改为静态 Passives/Progression；Story 只补同步 |
| `RaceCatalog.lua` | 官方种族身份和技能目录 | 数据可以审核后转换，Lua 文件本身不能使用 |
| `RaceFeatures.lua` | 种族标签顺序和主动能力同步 | 改为静态授予与 Story 幂等同步 |
| `OriginFeatures.lua` | 七起源身份标签和基础能力 | 无 MCM 后改为固定规则；默认全部身份生效 |
| `OriginStoryRewards.lua` | 根据官方剧情 Flag 发放奖励 | 最适合迁入 Story，但 Flag 作用域必须逐项验证 |
| `ChaosMechanics.lua` | 受创、迷失、混沌之力、孤注、回响事件 | 只保留能被 Story/Stats 稳定表达的简化版 |
| `ChaosDuality.lua` | 在伤害结算前拆分并重写伤害列表 | 依赖 SE Hook；必须重新设计 |
| `ChaosNativeRoll.lua` | 使用 `Osi.Random` 的统一随机函数 | 改为 Story 随机查询或随机数据库分支 |
| `MechanicsFeatures.lua` | 按状态同步能力和可见层数 | 改为 Stats 状态、Story 计数 DB 和刷新规则 |
| `DebugLog.lua` | MCM 控制的调试日志 | 改为开发期独立调试 Goal，正式包默认不包含 |

## 5. Story 版能力边界

### 可优先迁移

- 起源注册、默认外观、背景、守护者入口；
- 静态武器、护甲、盾牌、乐器熟练；
- 18 项技能熟练与精通，不含固定 `+5`；
- 起源标签、种族标签、隐藏解锁被动、主动技能与法术；
- 通过官方剧情 Flag 判定的剧情奖励；
- 使用状态、被动、法术和 Story 数据库表达的随机结果；
- 通过独立状态条目展示详细正负面效果。

### 必须重写

- 每次直接伤害发生前读取和修改伤害列表；
- 对一次攻击的最终伤害做无歧义的动态减半或翻倍；
- SE 实体事件、Lua 计时器、客户端网络消息和 Ext 持久变量；
- MCM 中每角色开关和即时页面快照；
- SE 控制台 `!cor_power`、`!cor_allin`。

### 不应静默伪装

如果 Story API 无法可靠区分攻击、法术、持续地表、追加伤害或多目标伤害，机制必须缩小触发范围并在说明中写明。不得为了“看起来复刻成功”而把所有伤害事件混在一起。

## 6. 身份与奖励规则

### 种族身份

- 保留玩家创建时原生种族的正常能力；
- 追加全部官方可选种族/亚种身份标签；
- 保留现有 29 项额外种族主动技能与法术；
- 不额外发放已删除的 20 项种族被动；
- 高等精灵和高等半精灵戏法候选池、重复能力施法属性及排除项，应从 `official-data` 和生成脚本重新审计，不直接手抄。

### 七项起源身份

无 MCM 后按固定“全部开启”规则设计。基础能力沿用 SE 的当前边界：

- 阿斯代伦：吸血；
- 威尔：边境之刃；
- 卡菈克：汗液免疫和狂怒烈焰；
- 盖尔、莱埃泽尔、影心、邪念：只提供身份标签；
- 剧情成长不能按等级发放。

起源身份不应产生明显的肖像 BUFF 图标。

### 剧情结果奖励

规则目录以 `reference-se/docs/superpowers/specs/2026-08-22-origin-story-rewards-design.md` 和 `OriginStoryRewards.lua` 为核对源，包括：

- 阿斯代伦飞升能力；
- 盖尔耐色瑞尔魔球自爆、幽影法术位、幽影召唤和成神形态；
- 威尔两项契约剧情奖励，但不复制剧情装备；
- 卡菈克两阶段引擎升级；
- 邪念杀戮者形态和一次性律令：死亡；
- 莱埃泽尔与影心目前仅保留身份，不把剧情装备转换成能力。

真实起源队友达成结果时，混沌角色也可认领奖励。永久奖励认领后不撤回；可撤销结果跟随官方 Flag；一次性奖励必须记录消费状态。Story 实现必须重新验证全局 Flag、角色 Flag、数据库时序及读档补发，不能只照搬 Lua 规则名。

## 7. 建议实现顺序与 Git 检查点

每一步单独提交，游戏内失败时可以回退到上一个检查点：

1. **工程与工具链**：确认 Story 编译器、LSLib、打包格式、模块 UUID、依赖和清单验证。
2. **最小起源**：只实现起源注册；验证新角色、默认男性半精灵、骗子背景、守护者、自由种族/职业/体型。
3. **升级基线**：从 1 级测试到 12 级，确保只在官方等级获得专长，不改 Progressions。
4. **基础静态能力**：熟练、18 技能精通及确定保留的初始能力。
5. **种族身份**：先标签，再 29 项主动技能/法术；确认没有额外种族被动。
6. **七起源身份**：全部固定启用，标签不可见，基础能力符合目录。
7. **剧情奖励**：按角色逐组实现和提交，验证旧档补发、撤销、阶段替换和一次性消费。
8. **资源与显示**：图标、状态层数、按 `T` 展开的效果详情和四语本地化。
9. **简化随机核心**：先受创，再混沌之力/迷失/开天辟地，最后加入重新设计的两仪、回响和强化伤害。
10. **完整构建验证**：检查精确 PAK 清单、反向解包文件列表与 SHA-256，然后安装实测。

第 2、3 步没有通过前，不加入身份、奖励或随机机制。

## 8. 构建规则

- Story 版使用新的 `package-files.json` 或等价受控清单；不得沿用 SE 的 34 文件清单。
- 构建前先进行静态验证；验证失败必须终止。
- 打包后反向解包，比较 staging 与反向目录的文件列表和每个文件的 SHA-256。
- 构建成功才递增 Story 版自己的版本号；不要修改 `reference-se/version.json`。
- 安装前必须确认游戏已经关闭。
- 编译成功、安装哈希一致和游戏内通过是三个不同的验收结论。
- Lua 中的中文注释要求不适用于 Story Goal；新 Story 代码应使用清晰中文注释说明规则和 Flag 语义。

## 9. UUID、命名与共存决策

开始编码前必须先由用户确认 Story Lite 与 SE 版是共存还是互斥：

- **共存**：生成全新的模块 UUID、模块目录名、起源 UUID、起源标签 UUID、资源 UUID、文本句柄和 Stats 前缀；避免两个起源同时污染同一存档。
- **互斥替代**：仍建议保留独立模块 UUID，除非明确需要继承旧存档；复用 UUID 前必须设计迁移和卸载路径。

未确认前不要创建最终 `meta.lsx`，也不要猜测 UUID 兼容策略。

## 10. 首轮验收清单

- 游戏和模组管理器能识别模块，无无效 UUID/依赖警告；
- 创建角色时出现且只出现一个混沌起源；
- 默认外观为男性半精灵，背景为骗子，但种族、职业、体型可修改；
- 守护者创建正常；
- 1–12 级官方升级和专长成长正常；
- 未安装 Script Extender 和 MCM 时仍能运行；
- 七起源身份与种族身份标签能触发预期对话判定；
- 不会额外获得全部种族被动；
- 所有奖励和随机机制重复读档不会重复堆叠；
- 状态图标、层数、剩余回合和详情分别表达正确含义。
